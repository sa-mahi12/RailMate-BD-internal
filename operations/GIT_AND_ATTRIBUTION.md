# Direct-main version control and authenticated author rules


The exact two repositories are `OWNER/RailMate-BD` and `OWNER/RailMate-BD-internal`. Both default private and have only main. The docs repo stores detailed documentation, coordination, agent packets, tests, logs, decision records and reports. The code repo stores app source, migrations, scripts, CI, needed short `AGENTS.md` and local skills; it links to internal docs in owner-only contexts rather than exposing private content. `gh repo create ... --source ... --remote origin --push` is only allowed after identity verification and explicit owner confirmation.

Only the coordinator calls `git add -- <reviewed paths>`, `git commit` and `git push origin main`. Each time it first verifies `gh api user`, per-repo `git config user.name` and `user.email` and whether this email is account verified or account-specific noreply; if mismatch, STOP. Workers must not run commit/push. Do not add `Co-authored-by: AI` or fabricated human credit; the commit author must be the real authenticated GitHub account. This rule does not authorize hiding AI assistance where the course has a disclosure requirement, and a genuine human collaborator's work cannot be falsely claimed as one's own.

No pull requests, merge commits from branches, feature branches, release branches, fork clones or Git worktrees that create branches. `git branch -a` and `git ls-remote --heads origin` must show only main. Do not configure branch protection that requires PR review; instead use coordinator's scripted post-pass checks and CI status. No force push, hard reset or destructive `git clean` without owner-specific approval. Fix errors with forward commits. Docs repo commits separately after its state is updated. If a push fails, retain local commit and retry verified remote; do not claim the remote has moved.
