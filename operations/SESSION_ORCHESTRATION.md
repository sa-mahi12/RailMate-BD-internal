# Two or three OpenCode worker sessions with machine guardrails


**Coordinator:** one AgentRouter DeepSeek session reads private CURRENT/CONTRACT/TASKS, plans bounded packets, launches independent `opencode run` child processes with verified `--model`, records exact session IDs and model versions, reviews outputs, integrates, performs checks, commits and pushes. It does not author feature code except explicitly logged emergency integration correction. **Worker A:** MiMo free model, one disjoint path family. **Worker B:** Muse free model, another disjoint path family. **Optional C:** only if >6 GiB free available RAM and no heavy build; never assume it can be a third independent session by writing `@agent` in a single prompt.

Prior FindBack evidence in the owner's coordination folder recorded WSL dropping to about 82 MiB free with swap fully used at five–six concurrent workers; avoid repeating that state. Start two sessions and inspect memory/CPU every 10–15 seconds via wrapper. Third is opt-in only after a measured stable two-session baseline. If available memory <2 GiB, terminate or pause newly launched off-critical-path worker; if <1 GiB or swap saturation, stop all workers gracefully and record state before OS hangs. Only coordinator may run Flutter pub get/analyze/test, Sass compilation, Node install, Gradle/Android build and large ZIP scans, guarded by one exclusive `heavy.lock` (atomic directory, trap cleanup). Never use `rmdir` to release a lock on drvfs/Windows mount because desktop.ini can be auto-created; use owner-verified process identity then `rm -rf` only the exact lock directory.

**File ownership:** Each packet has `allowed_paths`, `excluded_paths`, predecessor task, interfaces frozen and named reviewer. Workers cannot modify `.github/`, migrations, `AGENTS.md`, `opencode.jsonc`, schema, `.env`, Git metadata, sibling repo, or another worker's directory without new packet. Workers never commit/push/apply SQL. If a worker attempts a shared file, stop, create coordinator-owned integration packet, and serialize. The third worker is review-only while code workers are active if resource headroom is narrow.

**One branch:** No git worktrees, checkout -b, switch -c, PR generation or stash-based competing branch. Shared worktree concurrency requires disjoint file paths, not wishful isolation. Snapshot `git status --porcelain`, SHA, and assigned paths before each task. Coordinator stages explicit paths only, never blindly `git add -A` across concurrent edits. Each direct main push waits for post-pass gate and CI outcome; a remote push failure must not be disguised as success.

**Session resume:** `opencode run --session ID --model VERIFIED_MODEL` when supported by installed CLI; record actually returned IDs. A fresh `opencode run` creates a distinct session unless resumed; session labels and model claims are not evidence. Limit output/read sizes and a max total task duration; on stall, request a handoff before termination; if impossible, compare on-disk diff and logs to preserve usable work. No background tasks are promised by this static ZIP.
