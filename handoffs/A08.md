## Proposed focused unit test body (for coordinator to place, e.g. `test/board/reactions_ratings_test.dart` — NOT placed by worker)

1. One-vote toggle: fake rows `[]`; `toggle(post: p1, user: u1, LIKE)` → upsert called once with `LIKE`, `likeCount == 1`, `myReaction(u1) == LIKE`; `toggle(u1, LIKE)` again → delete called once, `likeCount == 0`, `myReaction(u1) == null`; `toggle(u1, LIKE)` then `toggle(u1, DISLIKE)` → upsert called with `DISLIKE`, `likeCount == 0`, `dislikeCount == 1` (replace, one row for u1).
2. Star range negatives: `setStars(stars: 0)` and `setStars(stars: 6)` return false with `upsertRating` NEVER called and `errorMessage` set; `PostRating.create(stars: 0)` and `PostRating.fromMap({'stars': 9, ...})` throw `ArgumentError`; `setStars(stars: 5)` → upsert called once, `myStars(u1) == 5`.
3. Aggregate recompute, no duplication after refetch: seed fake fetch returning 2 LIKE + 1 DISLIKE rows → `likeCount == 2`, `dislikeCount == 1`; call `load` again with the SAME fake list → counts still 2/1 (rows replaced, not appended); ratings fake with stars [5, 3] → `averageStars == 4.0`, `ratingCount == 2`; refetch same list → unchanged.
4. Invalid stars rejected + isolation: `setStars` with `postId: ''` returns false without upsert; `load(p1)` with a fake returning rows for p1 AND p2 keeps only p1 rows.

## Negative tests (manual reasoning, not executed)

- Same-value second vote removes the row (no duplicate PK violation path client-side; server PK `(post_id,user_id)` is the backstop).
- Stars 0/6/negative never reach the injected upsert; server `CHECK (stars BETWEEN 1 AND 5)` is the backstop.
- Refetch after reconnect discards the old list, so counts cannot double.
- Empty post/user ids short-circuit with an error and no injected call.
- Corrupt row maps (unknown reaction string, out-of-range stars) throw `ArgumentError` at parse time.
- `submitting` guard drops overlapping toggles/writes.
