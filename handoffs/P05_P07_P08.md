## Real bugs found and fixed (not just polish)
1. **Login "Forgot password?" was a dead end** — it opened a dialog reading
   "Password reset email is not wired in this slice", while P06 had already
   shipped the real flow (`requestPasswordReset` / `updatePassword`, route
   `/forgot-password`, deep link `railmatebd://auth/reset-password`). The
   screen's own doc comment was also stale. Now navigates to the real
   `ForgotPasswordScreen`; no stale copy remains.
2. **Live username availability was never wired** — `UsernameField` +
   `AppDependencies.checkUsername` existed but `routes.dart` built
   `RegisterScreen(auth:)` without a checker, so registration only did
   format checks. Verified on the live backend that `usernames_read` grants
   SELECT to `anon,authenticated`, so the check is safe pre-signup.
   `routes.dart` now injects a `UsernameAvailabilityChecker` built on
   `dependencies.checkUsername` **only when `dependencies.client != null`**
   (test compositions keep the format-gated field). Inconclusive verdicts
   throw inside the query so the field shows its honest "could not check —
   retry" state rather than a wrong green pill. The server unique constraint
   remains the final arbiter for races.

## P07 confirm-password (requested, additive)
`Confirm Password` field with its own obscure toggle, and a `_register`
gate: `Passwords do not match.`. Username is still optional; the gate only
runs after the existing username checks pass. A live `taken` verdict also
blocks submit (`That username is already taken.`).

## Test notes
- Auth sheets are long scroll views with several scrollables, so
  `scrollUntilVisible` is ambiguous — tests use a plain drag.
- `find.text('Create Account')` matches both the header title and the
  button; tests target `find.widgetWithText(ElevatedButton, ...)`.
- Non-zero entrance delays leave a pending fake timer, so auth tests
  `pumpAndSettle` after pumping.
