## What is REAL (no new backend, no invented data)
1. **Dynamic greeting** - `daypartForHour()` buckets the real local hour into
   morning (05-11) / afternoon (12-16) / evening (17-21) / night (22-04,
   salutation `Hello`). Signed in: `Good morning, Nabila` etc. using
   `AuthState.user` display name via `homeDisplayName()`. Signed out (or blank
   name): neutral `Welcome to RailMate BD`. No hardcoded "Good morning" remains
   anywhere; a unit test asserts the greeting varies across the 24 hours.
2. **Station catalog load (bug fix)** - `SearchState.loadStations()` was never
   called anywhere in the app, so the Home From/To dropdowns (and therefore the
   whole search flow) had zero stations in production. Home now loads it once on
   first mount when `stations.isEmpty && status == idle`. Same repository
   (`SearchApi.fetchStations` / GraphQL first), no new call path.
3. **Popular demo routes** - `kDemoPopularRoutes` contains only station CODES
   that exist in the applied catalog (DAC, CGP, SYL, RJH, KHL - all applied by
   `20260928000001_demo_horizon.sql` section 1) plus the demo service name from
   the applied service list. Cards are resolved at build time against the LIVE
   `SearchState.stations`; a code missing from the DB is dropped, so an invented
   route cannot render. Tap pre-fills From/To (no auto-search). 6 shortcuts
   (pack asks 5-8). A test pins every code against the applied code set.
4. **Recent searches** - real interaction history only: written solely after a
   `SearchState.search()` that returned `loaded`; max 5, newest first, deduped
   on origin>destination@date; `Clear all`; tap restores route + date (station
   ids resolved against the live catalog; unresolvable station -> honest
   snackbar, never a half-restored route). Empty state is honest and never
   preseeded. Persisted through an injectable `RecentSearchStore`
   (`InMemoryRecentSearchStore` session default; `SharedPreferencesRecentSearchStore`
   provided for on-device persistence and degrades to empty on any platform
   failure).
5. **Demo horizon limit** - date picker is now `firstDate = today`,
   `lastDate = today + 20` (pack 09 / `refresh_demo_horizon`), the strip hides
   past days, chips beyond the horizon are non-tappable, and submitting a date
   past the horizon shows `Demo schedules are available for the next 20 days.`
   without calling the repository. (`SearchState.validateSelection` was left
   untouched so V3 state tests keep their meaning.)
6. **Demo-data info action** - `HomeDemoNotice` shows the pack copy verbatim:
   "Schedules, fares and seat occupancy shown in RailMate BD are demonstration
   data." The booking card repeats `Demonstration ticket - not valid for travel`.

## What is a DOCUMENTED SEAM (needs coordinator wiring; nothing fabricated)
1. **Greeting display name** - `HomeSearchScreen` takes an optional
   `AuthState? auth`. Until the shell passes it, the greeting stays neutral.
2. **Upcoming booking** - `UpcomingBookingSection` accepts
   `LoadUpcomingBooking? loader` (+ optional pre-resolved `booking`,
   `onViewBooking`, `onFindTrain`, `onSignIn`). Unwired (current default) it
   renders `No upcoming bookings` / `Sign in to see your tickets`. Loading
   failure renders `Could not load your bookings` + Retry - never "no bookings".
   Model + wiring snippet: `lib/features/search/home/upcoming_booking.dart`.
3. **On-device recent-search persistence** - pass
   `recentSearches: SharedPreferencesRecentSearchStore()` to keep history across
   app launches.
