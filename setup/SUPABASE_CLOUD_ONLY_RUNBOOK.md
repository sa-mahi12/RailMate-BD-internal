# Cloud-only Supabase creation and acceptance

1. Owner logs into official Supabase Dashboard and selects their own organization. Choose an acceptable plan/region and turn on budgets/alerts where available. Record project ref privately, public URL and publishable key in local ignored app config. Do not copy database password/service-role key to source or AI prompts.
2. Configure Auth: email/password confirmation, Android redirect deep link, and only after separate approval SMS provider for real phone OTP. If no provider/budget, mark R-05 BLOCKED; do not invent a working SMS flow.
3. Review `DRAFT_initial_schema.sql`, `DRAFT_rls.sql`, `DRAFT_booking_rpc.sql`, `DRAFT_storage_policy.sql` in private docs. They are source proposals, not migrations applied to your project. In a new empty project, stage them as separate forward-only source migrations after SQL review; in a populated project take DB and separate storage backups first.
4. For day-to-day data access, Flutter uses only hosted Supabase SDK. No `supabase start`, no local database migration test server, no SQLite/Isar/Hive business data. Hosted staging can be a separate **Supabase project** only if owner approves cost/extra project; it is not an extra GitHub repository.
5. Enable pg_graphql through dashboard after confirming available extension/version, introspect actual station field. Generated REST comes from Supabase Data API. RLS and grants protect both API surfaces; don't build separate GraphQL and REST servers.
6. Set Storage bucket `post-media` size/MIME policy; enable Realtime publication only for necessary public board tables. Monitor quotas; no mass stress runs in production. Edge Function env holds service-role key; callable booking RPC grants service_role only. Remember: bucket metadata/database backup is not a backup of object bytes.
7. Before CI/app first build, verify nonempty Supabase public URL and publishable key. If GitHub Actions variables are unset, fail the integrated build rather than silently ship empty configuration. Confirm app binary does not contain service-role/AgentRouter/OpenRouter developer credentials.
